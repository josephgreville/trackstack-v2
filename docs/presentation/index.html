1 · The idea: what it is

One album. Many collections. Your copy.

The album is shared. The physical record on your shelf is personal.

  • A record lives in a shared catalogue.
  • Your copy has its own format, condition and price.
  • A collection is a shelf you can share.
  • The brief offers Route A or B. I chose records.

The interesting part

One album can sit in many collections, but your copy is personal. Its condition and price belong to you, not to the album. That is the relationship this app is built around.

3 · How it works: core functions

Four jobs, one path

React shows it. The API I built checks it. Postgres keeps it. iTunes supplies the catalogue.

Find a record

React → API → iTunes

Catalogue data only. The browser never calls Apple.

Save your copy

React → API → Postgres

The album is stored once. Your copy sits on the join table.

Build and share shelves

React → API → Postgres

Ownership is checked before a private shelf opens or a public link is shared.

Follow collectors

React → API → Postgres

Follows, likes and comments are stored as relationships, not copies.

3 · How it works: the one idea that matters

Shared album. Personal copy.

Store the album once. Store each person's copy separately.

Shared

The album

title · artist · year

One row per record. Everyone sees the same album, so the catalogue is never duplicated.

↔
linked by
collection_albums
Personal

Your copy

format · condition
price · notes

One row per shelf. Only you can change it, and only you see your condition and price.

Editing your copy never changes anyone else's album. The database enforces the link.

Why one URL

Safe redeploys

Migrations run at container start and can be repeated. A split hosting option and a local Docker path are documented.

6 · Reflection: what I learned

What worked, what didn't

Three things I'd keep, three I'd change, and three lessons.

Worked

  • Schema first, so every feature followed
  • One feature per commit
  • AI wrote code inside boundaries I set

Didn't

  • Scope was too big
  • The first UI looked generic
  • Free hosting sleeps on demo day

Learned

  • A collection is a join table, not a list
  • Real-database tests catch more
  • Saying no is part of design
